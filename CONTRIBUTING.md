# Contributing

Thank you for reading closely enough to want to fix something.

## What's welcome

- **Corrections.** A wrong number, a wrong claim, a code example that doesn't run, a figure that doesn't match the text, a typo. Open an issue or a pull request. Please say which chapter and section, and if it's a factual correction, point to a source.
- **Places you got stuck.** If a chapter lost you, that is a bug in the chapter, not in you. Open an issue titled "Chapter NN: I got lost at …" and say what you expected and what you found. These are the most valuable reports this book can get.
- **Additional labs.** A different way to do a chapter's lab (other hardware, other OS, no hardware) is welcome as a pull request adding a section under "Going further" or an alternative in "What you'll need."
- **Translations and accessibility fixes.** Open an issue first so we can agree on where they live.

## What's not in scope

- Rewriting a chapter's voice or structure. The book has one voice on purpose.
- Adding chapters or topics. The plan is fixed (see the status table in the README); propose a change as an issue and expect a conversation.
- Anything that isn't original. No copied text, traced figures, or code lifted from elsewhere.

## How to submit

1. Fork, branch from `main`, make the change.
2. For a chapter change, keep to the chapter's existing structure and vocabulary (`docs/GLOSSARY.md`). If you add a source, add it to the chapter's Sources and to `docs/BIBLIOGRAPHY.md`.
3. For a diagram change, match the palette, line weights, and shapes of the figures already in that chapter.
4. Open a pull request and say, in a few lines, what changed and why.

Kyle reviews and merges. Be patient; this is one person's book and he also has a day job.

## Conduct

Be kind. Assume the author and the other readers are trying. Disagree about facts with sources, not volume.
